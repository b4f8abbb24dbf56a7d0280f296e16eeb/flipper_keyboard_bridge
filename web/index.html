Through your Flipper.

Chrome captures a physical keyboard over Web Bluetooth, sends key states to the Flipper, and the Flipper types them into the USB host as a real HID keyboard.

Chrome / Edge on desktop, or Chrome on Android. Web Bluetooth requires a secure page; this one is published via GitHub Pages.

Setup

Four steps

  1. 1
    Prepare the Flipper

    Turn Bluetooth on, copy the FAP to the SD card, and launch BLE Keyboard Bridge. The screen shows BLE and USB status.

  2. 2
    Plug into the target

    Connect the Flipper to the host with USB. Wait until the Flipper screen says USB READY.

  3. 3
    Pair from Chrome

    Press Connect Flipper, pick the entry starting with “Flipper”, then confirm the PIN shown on the Flipper in the OS pairing dialog.

  4. 4
    Type

    Click the capture pad and type. Modifier and navigation keys are forwarded too.

Use Chrome on a different device from the USB host. If both are the same computer, the injected keystrokes land back in this page and can form a feedback loop.

Troubleshooting

If it does not work

The Flipper does not appear

Enable Bluetooth, make sure no other app is using the serial profile, and check that the FAP is running. If you renamed the Flipper, use “Show all BLE devices” at the bottom.

Pairing or PIN fails

Remove the old Flipper pairing, relaunch the app, and try again. If Chrome never shows a PIN dialog, pair the Flipper once from the OS Bluetooth settings while the app is running, then press Reconnect.

Connected, but nothing types

Check the Flipper screen: USB must show READY. Close qFlipper if USB switching is stuck. The capture pad must have focus, and Web Bluetooth must be available.

Wrong characters

This app sends physical HID positions. Change the target host's keyboard layout to match the keyboard you are typing on, or expect QWERTY-position output.

Keys stuck down

Press Release all, click outside the capture pad, or disconnect. The Flipper also releases everything after five seconds without a state heartbeat.
